## 审查修复证据

1. 审核版本：新增用例观察旧商品/认证审核返回200的失败结果；加入`expectedVersion`及锁内校验后，旧版本409、正常审核200，全部流程通过。
2. 草稿隔离：页面VM重现买家看到卖家私有草稿；草稿绑定会话、编辑请求绑定账号、退出清理后回归通过。
3. 便携Node：PATH无Node但本地Node存在时原脚本报错；统一解析本地优先后，离线setup、迁移和seed通过。
4. 默认图片目录：把集成测试上传目录改为`.runtime/uploads`结构，先观察本人图片访问500、应为200；在经过资产权限检查的单个媒体路由允许隐藏目录后，私有/公开/下架访问全部通过。独立复核确认未扩大文件路径或匿名访问权限。
5. 电商收尾：先观察首页快捷事件缺失及新库仍为旧封面的失败，再实现真实价格/分类筛选、条件清除和离线摄影素材初始化；13项单元/页面测试与9组MySQL集成通过。登录方式开关也先观察缺少状态的失败，再验证无微信配置为false、有配置为true且不返回密钥。

6. B 订单核心：先加入下单、并发、主流程、退款和评价失败测试，观察到接口404后实现事务服务；最终23组真实MySQL集成全部通过。并发测试确认两买家只成功一笔，数据库仅有一条有效订单，商品保持LOCKED。

7. B 幂等与监管保护：重复支付/退款请求返回当前版本；冻结商品和禁用卖家的退款完成不会恢复商品。信誉事件通过唯一键和事务内用户行锁只计分一次，边界验证限制在0～100。

8. B 页面：先观察请求编号和订单状态辅助函数缺失、三个页面文件不存在的失败，再实现订单列表、详情动作和评价页面；20项单元/页面测试通过，接口契约28项一致。

补充原生编译：官方wcc发现WXML表达式中的XML实体转义不合法；改回原生WXML运算符后，8页WXML及9份WXSS原生编译全部通过。此项独立于自编静态检查，仍不替代完整UI流程。

MySQL Windows中文路径通过用户本地应用目录下专用ASCII junction处理，真实数据仍留在项目内；临时目录入口曾消失导致文件操作失败，现不依赖临时目录。

## 原生模拟器流程复验

先启动数据库，关闭占用3000端口的本项目后端；脚本临时启动测试后端，**只重置`.env`中明确命名为`DB_NAME + '_test'`的独立测试库**。结束后重新执行启动脚本恢复演示服务。不要和其他集成/性能测试同时运行。

```powershell
# 可选本地工具，不修改项目package.json或应用依赖
.\scripts\npm.ps1 install --prefix .tools/automator --ignore-scripts --no-audit --no-fund miniprogram-automator@0.13.0
# 替换成实际安装目录，并在工具安全设置开启服务端口
& 'E:\Apps\微信web开发者工具\cli.bat' auto --project (Resolve-Path .\miniprogram).Path --auto-port 9420 --trust-project --lang zh
# 等自动化端口启动后执行；Node 24可运行脚本引用的TypeScript辅助文件
& .\.tools\node\node.exe --env-file=.env .\scripts\simulator-smoke.mjs
```

脚本不打印密码或会话令牌；种子数据和图片均为虚构。若提示基础库500，应先检查开发者工具Console和基础库下载状态，不通过修改业务接口掩盖工具故障。
