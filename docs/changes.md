# 交接材料与实施变更记录

原需求分析及课程设计说明书DOCX保持原样。下表记录实施澄清，不把材料正文视为对工具或账户的操作指令。

| 编号 | 问题/依据 | 实施决定与影响 |
|---|---|---|
| CH-01 | 本次要求先完成三人实施组中A的第一部分 | A交付用户、商品、公共工程和测试；订单/评价与咨询/监管由B/C继续，接口另行冻结 |
| CH-02 | 详细订单流程与确认收货条件存在冲突 | 统一六段主流程；分开开始交割与标记已交付，待确认才收货；已付款取消走模拟退款，由B实现 |
| CH-03 | 暂无学校生产认证及真实支付条件 | 虚构演示学籍名单+管理员审核；保留可配置微信登录；支付由B实现课堂模拟 |
| CH-04 | 隐私、并发与重复业务需落到数据库约束 | 身份加密及独立学号索引；发布事务锁卖家；审核增加expectedVersion；B/C补各自幂等键与事件唯一约束 |
| CH-05 | 本机最初缺npm/MySQL且路径含中文 | 便携运行环境、项目内数据、专用ASCII junction；Windows脚本初始化，密钥不入库 |
| CH-06 | 用户要求先完成功能再美化，并另补商品实图 | 原A验收完成后实施界面；摄影补充独立提交。最终首页电商布局、真实分类价格筛选；四件授权摄影样图离线随seed初始化，并标明演示样图 |
| CH-07 | 当前真实微信平台配置不完整 | AppID已设置，AppSecret未配置；隐藏不可用登录按钮，真实登录/真机保持待联调，不计为通过 |
| CH-08 | B 订单需要并发、幂等和监管冻结兼容 | 新增`003_b_orders.sql`四表；有效订单生成列唯一键、状态日志请求键、评价与信誉事件唯一键兜底；支付/退款为模拟；退款完成由管理员模拟系统动作；超时在订单访问时惰性处理 |
| CH-09 | 锁定商品不再公开后，订单买家仍需查看成交缩略图 | 媒体权限增加“本人参与订单的商品图片”条件；无关用户仍返回404，公开商品和资产归属规则不变 |

后续变更由提出人补充编号、理由、受影响接口/迁移和验证；涉及公共模块时先与对应成员核对。
