# 功能接口与项目交接契约

这是统一项目 `main` 的功能接口和开发接续说明。完整请求/响应以 [OpenAPI](openapi.json) 与当前服务端代码为准；本页说明模块边界、公共规则和下一步协作方式。

## 业务模块

| 模块 | 主要功能 | 代码位置 |
|---|---|---|
| 用户与认证 | 登录会话、个人资料、学籍认证、审核和脱敏 | `server/users`、`server/auth` |
| 商品 | 图片、发布、审核、检索、编辑、上下架 | `server/products` |
| 订单 | 下单、支付、状态流转、超时、退款、纠纷和商品锁 | `server/orders` |
| 评价与信誉 | 双向评价、唯一信誉事件、分数边界 | `server/orders` 与公共信誉服务 |
| 咨询与收藏 | 会话参与者隔离、消息幂等、收藏状态 | `server/chat`、`server/favorites` |
| 举报与监管 | 举报、处置、冻结、账号、分类、规则与审计 | `server/moderation`、`server/admin` |

页面、路由、服务和仓库分别处于 `miniprogram`、`server/app.ts`、各业务目录和 `server/db`。共享鉴权、统一响应和事务工具由公共层提供，功能代码通过当前模块接口调用，避免多个页面自行修改业务状态。

## API与数据约定

- API前缀 `/api`；统一响应 `{code,message,data,requestId}`，错误状态通过HTTP状态码表达。
- 会话令牌使用 `Authorization: Bearer <token>`，不放在URL、日志或普通页面数据中。
- 金额以整数分保存和传输；数据库编号在JSON中按字符串处理；列表默认每页20条。
- 客户端提交动作、版本和请求编号；服务端检查角色、所有权、业务状态、版本和幂等约束。
- 数据库结构只通过新编号迁移追加；已执行迁移不可修改。迁移摘要用于检测文件漂移。
- 成立举报、订单完成和评价等信誉事件在同一数据库事务内调用唯一事件服务，不能直接更新信誉分。

## 订单状态与交易保护

权威动作见 `server/contracts.ts` 的 `ORDER_TRANSITIONS`，详细流程见[订单模块说明](orders.md)。关键规则：

1. 下单事务按固定顺序锁买家、交易双方和商品，重新读取商品价格并条件更新锁定状态。
2. 重复下单请求使用请求编号幂等；数据库有效订单唯一约束防止同一商品被重复占用。
3. 支付和退款只接受明确动作；过期订单扫描不绕过状态机。
4. 退款完成前商品不恢复在售。监管冻结、账号禁用与订单锁定是独立条件，互不覆盖。
5. 确认收货后，买卖双方分别产生一次完成信誉事件；每人对同一订单最多评价一次。

## 隐私与安全

实名字段加密存储；学号使用独立不可逆索引校验重复。本人界面只展示脱敏字段，公开商品资料不返回学号。所有权、监管权限和敏感媒体读取必须由后端检查。提交前确认没有 `.env`、`.runtime`、开发者工具账号数据或真实身份材料。

## 本地接手

从仓库根目录按 [协作说明](../CONTRIBUTING.md) 克隆并运行 `main`。新功能须带接口文档、迁移（如需要）、自动化验证和课堂展示说明；对既有功能的修改应说明影响并补充回归证据。后续未完成事项见[统一任务规划](tasks.md)，实现与展示入口见[报告索引](implementation-report/README.md)。
