# 项目课堂演示

建议用6～8分钟展示“业务闭环、设计依据、测试证据”。流程围绕一个完整项目展开；各演示身份均为虚构，本地密码从 `.env` 读取，投屏时不要打开密钥或配置文件。

## 展示前准备

- 启动数据库和后端，健康检查返回 `status:ok`。
- 微信开发者工具导入 `miniprogram`，使用课堂演示登录。
- 确认演示库仍有可售商品；不清空已留存的交易或举报记录。
- 确认模拟器使用本机后端地址，不要将本地 `127.0.0.1` 当作手机可访问地址。

## 演示步骤

| 顺序 | 操作 | 讲解重点 |
|---|---|---|
| 1 | 从首页搜索商品，查看分类、价格筛选和详情 | 列表由真实接口提供，卖家信息按规则脱敏 |
| 2 | 登录未认证演示身份并提交实名资料 | 虚构学籍匹配、加密保存、重复学号检查 |
| 3 | 管理员审核认证 | 后端角色校验、审核理由与版本冲突处理 |
| 4 | 认证用户上传图片发布商品；管理员审核 | 上传检查、待审不可见、编辑后重新审核 |
| 5 | 买家从详情发起订单并模拟支付 | 服务端价格快照、订单事务锁定和请求幂等 |
| 6 | 卖家接单并完成交割，买家确认和评价 | 状态机动作权限、订单完成及唯一信誉事件 |
| 7 | 展示咨询、收藏、举报和监管处置 | 会话参与者隔离、本人举报记录和冻结状态 |
| 8 | 查看测试表或一条并发/越权测试证据 | 黑盒业务流程、白盒逻辑及MySQL事务验证 |

## 讲解口径

“前端负责输入与状态展示，服务端按 Controller、Service、Repository 分层执行权限、业务状态和事务。认证和商品审核防止未经校验的内容公开；下单时服务端重新读取价格并锁定商品，订单状态只能通过明确动作前进。成立举报和信誉事件共用事务，数据库唯一约束防止重复处理。测试覆盖业务流程、安全边界和并发场景。”

## 演示范围

- 订单支付、退款和管理员确认退款均为课堂模拟，不接真实资金渠道。
- 学籍名单为虚构样例；真实微信平台登录需配置服务端 AppSecret 并另行验收。
- 20张界面原图和4张流程图均列在[PPT素材目录](implementation-report/ppt-assets/README.md)。授权摄影样图不是小组真实待售物品的实拍。
- 本地模拟器流程不代表真机网络、线上部署或微信搜索发布已通过。
